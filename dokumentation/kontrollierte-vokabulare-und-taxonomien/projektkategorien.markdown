```Project Categories```

<br/>

Permanent URL: [http://w3id.org/arkumu/project-categories](http://w3id.org/arkumu/project-categories)

---

<br/>

**Deutsch:**

Projektkategorien geben die Kunstgattung oder das Genre eines Projekts an – siehe [Entitäten und Attribute des Datenmodells](/resources/entities-and-attributes-of-the-data-model.html#projekt-projektkategorien).

Um das System leicht pflegebar zu halten, verwendet arkumu.nrw für die Projektkategorien keine ontologische Struktur, auch wenn eine hierarchische Taxonomie ihnen streng genommen nicht gerecht wird. Dies hat zur Folge, dass manche Begriffe in mehreren Hierarchien gleichzeitig auftauchen. Beispiel: Der Begriff "Drehbuch" kann den übergeordneten Begriffen "Film/TV" oder "Literatur" zugeordnet sein, je nachdem, in welchem Lehrgebiet das Projekt entstanden ist. Es können aber auch beide zutreffen. Ontologien können ein solches "child" mit mehreren "parents" problemlos abbilden; Taxonomien nicht. Deshalb taucht der Begriff mehrmals auf. Beim Erfassen eines Projekts ist deshalb immer der gesamte Hierarchiebaum ("breadcrumb") zu berücksichtigen; es ist zu überlegen, ob das Projekt besser in "Film/TV" oder "Literatur" passt. Im Zweifel können beide zugeordnet werden.

Nicht zu verwechseln mit [Projektarten](/documentation/controlled-vocabularies/project-types), die den akademischen Kontext eines Projekts klassifizieren.

ⓘ Im Folgenden wird zur besseren Lesbarkeit und Auffindbarkeit das initial erstellte Vokabular aufgeführt. Die auf [GitHub](https://github.com/arkumu/vocabs.arkumu.nrw) gepflegte und über GitHub Pages auf [https://vocabs.arkumu.nrw/](https://vocabs.arkumu.nrw/) veröffentlichte Fassung ist möglicherweise aktueller und als verbindlich anzusehen.

<br/>

---

<br/>

**English:**

Project Categories specify the art form or genre of a project – see [Entities and Attributes of the Data Model](/resources/entities-and-attributes-of-the-data-model.html#projekt-projektkategorien).

To keep the system easily updatable, arkumu.nrw does not use an ontological structure for Project Categories, even though, strictly speaking, a hierarchical taxonomy doesn't do them justice. This means that some terms appear in multiple hierarchies. Example: The term “screenplay” can be assigned to either the broader term “Film/TV” and “Literature”, depending on the academic discipline in which the project was created. It's also possible that both are correct. Ontologies can easily represent such a “child” with multiple “parents”; taxonomies cannot. That is why the term appears multiple times. When creating a project, the entire hierarchy tree (“breadcrumb”) must therefore be taken into account; it should be determined whether the project is better suited to “Film/TV” or “Literature”. If in doubt, it can be assigned to both.

Not to be confused with [Project Types](/documentation/controlled-vocabularies/project-types), which classify the academic context of a project.

ⓘ The vocabulary initially created is documented below for easier reading and reference. The version maintained on [GitHub](https://github.com/arkumu/vocabs.arkumu.nrw) and published via GitHub Pages at [https://vocabs.arkumu.nrw/](https://vocabs.arkumu.nrw/) might be more up-to-date and should be considered authoritative.
